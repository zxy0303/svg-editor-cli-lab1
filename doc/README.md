# Lab1 Phase 1：SVG 编辑器课程作业报告

**Git 仓库地址：[https://github.com/zxy0303/svg-editor-cli-lab1](https://github.com/zxy0303/svg-editor-cli-lab1)**

**最终版本：[final](https://github.com/zxy0303/svg-editor-cli-lab1/tree/final)**

本次作业使用 TypeScript 实现了一个命令行 SVG 编辑器，支持矩形、圆、椭圆、直线、文字和分组容器六种类型。通过命令可以完成图形的创建、修改、分组、层级调整、撤销重做，以及 SVG 文件的读取和保存。实现过程中使用 Codex 辅助讨论方案、编写代码和检查问题。

## 一、架构方案

### 1. 模块划分与依赖关系

我把项目分成六个模块，主要考虑是把图形本身的操作与命令行、文件读写分开。这样修改输入方式或保存方式时，不需要改动图形类。

| 模块 | 职责 | 允许依赖的其他模块 |
| --- | --- | --- |
| `domain` | 定义图形、容器和文档，处理几何变化、父子关系和 ID 约束 | 无 |
| `application` | 管理当前文档、执行编辑操作和维护撤销重做历史 | domain |
| `commands` | 将输入对应的操作封装为命令对象 | application、domain、presentation |
| `cli` | 读取和拆分输入、分发命令、输出结果，并完成启动时的对象装配 | 其余五个模块 |
| `infrastructure` | 解析和生成 SVG，读写本地文件 | application、domain |
| `presentation` | 生成 tree 和 show 的显示内容 | domain |

这些模块分别放在 `src/` 下的同名目录中。依赖方向的基本原则是：领域层只处理图形和树结构，应用层组织操作，输入输出细节放在外层。文件系统和 XML 库不会被领域层直接调用；文件存储通过应用层的 `SvgStorage` 接口接入。

### 2. 设计模式及实现

**Command 模式。** 创建、删除、移动、分组等操作分别对应命令类，统一通过 `execute` 执行。编辑命令继承 `EditCommand`，在 `apply` 中完成具体修改，再由 `Editor` 统一记录修改前后的状态。这样即使一次分组涉及多个图形，也只算一条编辑命令，撤销一次就能恢复。

**Composite 模式。** `Shape` 是图形的共同抽象，`Rect`、`Circle` 等类表示叶子图形，`Group` 保存子图形。它们都提供 move、scale、set 等操作，命令通过同一套接口调用。普通容器的移动和缩放递归处理子图形；对于导入后已有变换的子树，容器移动通过外层平移保持整组的相对位置。

**Memento 模式。** 撤销重做保存编辑前后的文档快照，由 `History` 和 `EditRecord` 管理。选择快照的原因是分组、解组和删除容器会同时改变父子关系、顺序和多个对象，分别编写反向操作容易漏掉状态。快照的不足是复制成本较高，本阶段先用于小型文档，优先保证恢复正确。

按名字选择实现只保留在两个地方：`CommandDispatcher` 根据命令名分发，`ShapeFactory` 根据图形类型创建对象。这两处是方案中的**待重构项**，以后增加插件时再考虑改成注册方式。

### 3. 对后续变化的考虑

- **新增图形类型。** 使用统一的 Shape 抽象，并将类型创建集中在工厂中。box 和插件系统属于后续阶段，本次没有提前实现。
- **新增命令或交互方式。** 命令对象与文档操作不依赖终端输入，后续改用其他交互方式时可以复用。tree/show 的格式也单独放在展示层。
- **改变存储方式。** 应用层使用存储接口，目前只实现本地 SVG 文件读写，后续可以增加其他实现。
- **增大文档规模。** 历史管理集中在应用层，后续可以将完整快照改成差量记录。这次没有做大文档性能优化，因为课程案例规模较小。

## 二、过程记录

项目按工程搭建、图形模型、命令和历史、SVG 读写、检查修正的顺序分步完成。10 月 26 日完成主要功能，之后几次复查根据课程要求继续补充测试和修正，过程保留在 Git 提交记录中。和 Codex 协作时，主要通过对照题目、运行案例和补充测试来确认方案是否合适。以下是其中几次有代表性的调整。

### 1. 撤销重做需要恢复整棵树

分组和解组涉及的变化比较多，仅恢复某个图形的数值还不够，还需要恢复父容器和兄弟节点顺序。因此实现中采用文档快照，并检查跨父级分组和嵌套解组能否通过一次 undo 完整恢复。

测试还构造了一个前面的子图形已经修改、后面的坐标发生溢出的情况，确认命令失败后可以恢复原文档。这里的检查重点是整条命令是否完整完成，以及失败后有没有留下部分修改。

### 2. 重新核对保存路径的含义

初版把显式执行 `save B.svg` 理解为修改默认保存路径。重新对照题目后，发现无参数 save 应当使用读入时的路径。因此改为：read A 后另存为 B，再执行无参数 save，仍然保存到 A。新建文档没有 read 路径时，需要显式指定文件名，并加入了对应测试。

### 3. 外部 SVG 的 ID 和输入校验

自动补 ID 时，如果从前向后直接分配，匿名矩形可能先占用后面已有的 `rect1`。后来改为先收集全部显式 ID，再给缺 ID 的元素命名。

后续检查还发现，非法 XML 字符不能等到保存时才拒绝，否则编辑器中会留下无法保存的文档。因此将字符检查放到数据进入模型时执行。对注释和 CDATA 的处理也作了调整，避免仅凭文字中出现 DOCTYPE 等字样就误拒绝文件。

### 4. 补查带变换的容器移动

最后使用课程背景中的嵌套 SVG 示例检查时，发现 `move diagram 10 0` 会让普通矩形移动 10px，而 `scale(0.8)` 子组里的矩形只移动 8px。原因是给不同坐标系中的子图形增加同样的局部坐标，不能保证它们在画布上一起移动。

先增加两项回归测试复现问题，再修改 `Group.move`：当容器或子树已有 transform 时，在容器原有变换外侧增加平移。修改后检查了连续移动、撤销重做和保存读回，并通过本地 SVG 渲染对比，确认课程示例中的整张图一起平移了 10px。

## 三、一致性自查

### 1. 模块划分是否与方案一致

实际源码仍按前面的六个模块组织，`src/cli.ts` 只负责启动。图形类采用私有字段保存数据，一类一文件，文件名与类名一致。测试、示例和文档分别放在 `test/`、`examples/`、`doc/` 中。

实现过程中没有增加新的业务模块。修正 XML 输入和容器移动时，也是在原有类中调整相应行为，没有把文件读写或命令行逻辑放进领域层。

### 2. 依赖方向是否与方案一致

目前静态依赖检查通过，核对代码时也检查了以下关系：

- `Shape`、`Group`、`SvgDocument` 只依赖领域层内部的类。
- `Editor` 使用存储接口，不直接引用文件存储实现。
- `FileSvgStorage` 实现存储接口，实际文件读写放在基础设施中。
- `TreePresenter` 读取模型生成文字，展示层不反向调用命令。

初稿的图中漏画了 CLI 对领域层的依赖，因为 CLI 启动时需要装配 `ShapeFactory`，后来已补上箭头并同步调整规则。除此之外，实际模块与方案保持一致。命令分发和图形工厂仍保留为前面说明的待重构项。

## 四、质量保证手段

### 1. 功能与异常情况检查

项目使用严格类型检查，并编写了 43 项自动化测试，覆盖图形操作、命令与历史、SVG 读写、真实命令行案例，以及模块依赖等内容。测试中既检查正常结果，也检查失败后文档和历史是否保持不变。

重点检查的情况包括：

- 六类图形的创建、浮点参数、容器嵌套，以及 move/scale 的几何结果。
- 分组和解组后的顺序、删除容器后的子孙处理，以及每条编辑命令的 undo/redo。
- 新编辑清空 redo，显示命令不影响历史，成功的文档操作按要求禁止撤销重做。
- 重复 ID、无效参数、未知属性、文件读取失败和保存失败时，只输出错误，不留下部分修改。
- SVG 保存后读回，中文、特殊字符和额外属性能够保留，缺 ID 的元素得到唯一 ID 和警告。

### 2. 运行方式与案例

项目需要 Node.js 22 或更新版本。在项目根目录执行：

```sh
npm ci
npm run cli
```

输入 `help` 可查看全部命令。运行完整检查和课程案例的方式为：

```sh
npm run check
npm run --silent cli < examples/flowchart.commands
npm run --silent cli < examples/session.commands
```

目前编译、类型检查和 43 项测试均通过。GitHub Actions 也在 Node.js 22、24 环境通过了干净安装和检查，[结果记录见这里](https://github.com/zxy0303/svg-editor-cli-lab1/actions/runs/41188683638)。典型会话中非法分组、save 后 undo 的两条报错是题目预期结果，程序会继续执行。

### 3. 当前实现的范围

本次只实现课程要求的六类图形，box、插件系统和图形界面没有实现。path、tspan 等其他 SVG 元素，以及百分比等单位暂不支持。

含 transform 子树的容器移动以父坐标系为准；叶子图形的几何编辑和 scale 仍处理局部坐标，跨变换容器调整归属时没有做画布坐标补偿。撤销重做使用完整快照，也没有针对大型文档做性能优化。保留这些限制，是为了先把本阶段要求的功能和状态恢复做好。
